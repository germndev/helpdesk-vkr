# HelpDesk (ВКР)

Система автоматизации обработки заявок внутренней технической поддержки предприятия.

Этот README описывает проект в двух плоскостях:
- пользовательский функционал (что умеет система);
- техническую архитектуру (как реализовано и где находится код).

---

## 1. Назначение проекта

Цель проекта — сократить время обработки внутренних заявок за счет автоматической классификации и маршрутизации, при этом сохранив возможность ручной корректировки администратором/поддержкой.

Ключевые задачи:
- централизованный прием обращений;
- автоматическое определение категории и приоритета;
- автоматическое назначение ответственного сотрудника;
- прозрачный жизненный цикл заявки;
- чат внутри заявки с файлами и realtime-доставкой.

## 3. Ограничения предметной области

- Самостоятельной регистрации нет.
- Пользователей создает администратор.
- Роли:
  - `user` — сотрудник, который подает заявку;
  - `support` — сотрудник техподдержки;
  - `admin` — администратор системы.
- Статусы:
  - `new` — новая;
  - `in_progress` — в работе;
  - `resolved` — выполнена;
  - `closed` — закрыта.
- Классификация — rule-based на основе триггеров и весов.
- Если уверенность классификатора недостаточная — заявка помечается на ручную обработку (`needs_manual_review = true`).

## 4. Пользовательский функционал

## 4.1. Функции для роли `user`

### Создание заявки
Экран: новая заявка
- ввод заголовка;
- ввод описания;
- добавление вложений.

При сохранении автоматически выполняется классификация (`TicketClassifier`).

### Просмотр своих заявок
- отображаются активные и завершенные обращения;
- доступ только к собственным заявкам.

### Детальная карточка заявки
- статусы и поля заявки;
- вложения;
- чат с поддержкой.

### Чат
- отправка текста;
- отправка вложений;
- отправка по Enter;
- получение новых сообщений в realtime.

## 4.2. Функции для роли `support`

### Список заявок
- отображаются заявки:
  - назначенные на текущего сотрудника;
  - без ответственного (для подхвата).
- доступны фильтры по полям заявки.

### Детальная карточка
- просмотр всех ключевых атрибутов;
- переключение в режим редактирования;
- сохранение изменений;
- закрытие заявки кнопкой.

### Чат
- обмен сообщениями с пользователем в карточке заявки;
- поддержка вложений;
- realtime-обновление.

## 4.3. Функции для роли `admin`

### Управление заявками
- список + фильтры;
- просмотр детальной карточки;
- редактирование заявки;
- удаление заявки;
- закрытие заявки.

### Управление пользователями (`admin/users`)
- список пользователей;
- создание пользователя;
- редактирование профиля и роли;
- загрузка/обновление аватара;
- удаление (с защитой от удаления связанного/текущего пользователя).

### Управление правилами классификации (`admin/classification-rules`)
- список правил;
- создание/редактирование правила;
- включение/выключение активности правила;
- добавление/удаление триггеров;
- назначение ответственных сотрудников для категории.

### Дашборд
На главной странице админа/поддержки отображаются агрегированные показатели по заявкам.

## 6. Подробно: алгоритм категорий и приоритета

## 6.1. Нормализация текста заявки
Перед вычислениями объединяется `title + description` и нормализуется:
- перевод в нижний регистр;
- удаление лишней пунктуации;
- схлопывание пробелов.

Это обеспечивает стабильное сопоставление триггеров.

## 6.2. Алгоритм определения категории

Источник правил:
- таблица `classification_rules` (только активные);
- таблица `classification_rule_triggers`.

Шаги:
1. Для каждого правила берутся все его триггеры.
2. Если триггер найден в тексте заявки — добавляется его `weight`.
3. Получаем `score` по каждой категории.
4. Сортируем категории по score.
5. Берем лучший и второй результат.
6. Проверяем пороги уверенности:
   - `min_score` (минимум для принятия),
   - `min_gap` (отрыв от второго).

Если пороги пройдены:
- категория назначается.

Если пороги не пройдены:
- категория не назначается,
- `needs_manual_review = true`.

Текущие пороги (по умолчанию):
- `category.min_score = 3`
- `category.min_gap = 2`

## 6.3. Алгоритм приоритезации

Вычисляется `priorityScore` как сумма сигналов.

Группы сигналов:
- `urgent` — признаки срочности;
- `impact` — признаки массового влияния;
- `blocker` — признаки полной/критичной блокировки работы;
- `softener` — смягчающие признаки.

Правила подсчета:
- `urgent`, `impact`, `blocker` прибавляют вес;
- `softener` вычитает вес.

Преобразование score в уровень:
- `>= critical` → `Критический`
- `>= high` → `Высокий`
- `<= low` → `Низкий`
- иначе → `Средний`

Текущие пороги (по умолчанию):
- `low = -1`
- `high = 3`
- `critical = 5`

## 6.4. Алгоритм выбора исполнителя

После определения категории берутся ответственные сотрудники, привязанные к этому правилу.

Далее сотрудники ранжируются по критериям:
1. Онлайн-статус (активная сессия в окне `online_window_minutes`).
2. Меньше срочных активных задач (`Высокий`, `Критический`).
3. Меньше активных задач в целом (`new`, `in_progress`).

Победитель ранжирования записывается в `assigned_to`.

## 7. Чат и realtime

### Транспорт
- приватные каналы Reverb: `ticket.{ticketId}`.

### Авторизация каналов
Файл: `routes/channels.php`
- пользователь видит только свои заявки;
- support — только назначенные ему;
- admin — все.

### Механика
1. Сохранение сообщения в БД.
2. Сохранение вложений (если есть).
3. Broadcast события `TicketMessageCreated`.
4. Клиенты получают событие и запрашивают обновленный HTML сообщений.

### Надежность
Если websocket временно недоступен, включается резервный polling в JS.

## 10. Запуск проекта

## 10.1. Установка
```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
```

## 10.2. Проверить `.env`
Минимум:
- `DB_*`
- `BROADCAST_CONNECTION=reverb`
- `REVERB_*`
- `VITE_REVERB_*`

## 10.3. Запуск (3 процесса)
Терминал 1:
```bash
php artisan serve
```

Терминал 2:
```bash
npm run dev
```

Терминал 3:
```bash
php artisan reverb:start
```

## 12. Типовые проблемы

### Проблема: Vite не стартует из-за версии Node
Решение: обновить Node.js до совместимой версии с текущим Vite.

### Проблема: чат не обновляется в realtime
Проверить:
- запущен ли `php artisan reverb:start`;
- корректно ли заполнены `REVERB_*` и `VITE_REVERB_*`;
- доступен ли порт Reverb.

### Проблема: вложения не открываются
Выполнить:
```bash
php artisan storage:link
```
